# Stage 2 — Synthetic Data Generation

Generated by [src/generate_data.py](../src/generate_data.py), seed=42,
into [data/ab_test_data.csv](../data/ab_test_data.csv) (one row per user,
matching the unit of randomization and analysis unit from Stage 1).

## Simulated Assumptions (not real findings)
These relationships are hard-coded into the generator to give the dataset a
realistic, testable shape — they are not derived from any real business data:

- Control conversion probability baseline **0.10**; treatment gets a
  **+1pp lift** (0.11) — the effect this whole project is built to detect.
  (Revised down from an earlier +2pp draft, which produced an unrealistically
  large observed gap for a checkout redesign.)
- Device type and new-vs-returning status shift conversion probability
  slightly (±1–1.5pp), applied equally in both arms (no interaction with
  treatment).
- Guardrails (AOV ~lognormal($75), checkout error rate ~3%, refund rate ~5%
  of purchases) are drawn from the **same distribution in both arms** — any
  variant-level gap in the data is sampling noise, not a designed effect.
- Variant assignment, assignment_date, device_type, country, and
  new_vs_returning_user are all drawn independently of each other — no
  deliberate sample ratio mismatch or confounding.

## Validation Results (actual run output)
- Row count: **20,000**
- Duplicate `user_id`: **0**
- Missing values: **0** in every column
- Assignment split: control 9,938 (49.7%) / treatment 10,062 (50.3%) —
  close to 50/50 as expected from independent random assignment
- Primary metric (conversion rate):
  - control: **9.95%**
  - treatment: **12.16%**
  - observed absolute lift ≈ **+2.21pp**; relative lift ≈ **+22.2%**
    (larger than the +1pp designed base-rate lift because the
    device/returning-user effects and binomial sampling noise also
    contribute — formal significance testing is Stage 4, not this stage)
- Guardrails by variant (purchasers only where applicable):
  - AOV: control $79.50 vs treatment $81.56 (noise-level difference)
  - Checkout error rate: control 3.20% vs treatment 2.99% (noise-level)
  - Refund rate: control 4.45% vs treatment 4.09% (noise-level)

## Columns
| Column | Description |
|---|---|
| `user_id` | unique integer ID |
| `variant` | control / treatment |
| `assignment_date` | date within the 14-day experiment window |
| `device_type` | mobile / desktop / tablet |
| `country` | US / UK / CA / DE / IN |
| `new_vs_returning_user` | new / returning |
| `converted` | 1 if user completed a purchase (primary metric input) |
| `order_revenue` | order amount if converted, else 0 (AOV guardrail input) |
| `had_checkout_error` | 1 if session had a payment/form error (guardrail input) |
| `refunded` | 1 if the purchase was refunded, else 0 (guardrail input) |

## Notes
- No sample ratio mismatch or data corruption was deliberately introduced —
  that is reserved for a later validation/robustness exercise if desired.
- Formal statistical testing of these differences is out of scope for this
  stage (Stage 4: Python statistical testing).
